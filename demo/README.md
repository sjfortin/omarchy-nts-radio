# Demo mode

Runs the plugin against canned data instead of NTS.

```bash
# stop the running shell, then start it with demo mode on
while quickshell kill -p /usr/share/omarchy/shell --any-display; do :; done
hyprctl dispatch 'hl.dsp.exec_cmd("env NTS_DEMO=1 omarchy-launch-shell")'
```

`omarchy restart shell` puts it back to normal.

## Why

**Screenshots.** Every show, host, episode title and cover in here is invented,
and the artwork in `art/` is generated by the plugin's own script — so the
images shipped with this repository contain no NTS programme artwork and no
third-party photography. That matters because a marketplace submission asks you
to confirm you own the preview assets, and because NTS's cover art is mostly
other people's.

**Testing.** Live radio changes every hour. A show with a very long title, an
episode with no audio, an empty search, a part-heard episode on the "continue
listening" shelf — all of those are otherwise a matter of waiting for one to
come along. Here they are always present and always the same.

## What is stubbed

- The live schedule, so both channels always have something on.
- Search, shows, episodes, tracklists and the editorial collections.
- The saved library — demo mode loads a fixture library and **never reads or
  writes** `~/.local/state/omarchy/nts-radio/library.json`, so a screenshot
  cannot leak real saved shows and a demo session cannot edit them.

Nothing plays: the fixture audio URLs are not real. Demo mode is for looking at
the interface, not listening to it.

## Files

```
Fixtures.js   canned responses, shaped like the real endpoints
art/          8 generated covers, assigned to shows by a hash of their alias
```

Responses go through the same parsers as production data rather than around
them, so a parser change that breaks real NTS breaks demo mode too.
